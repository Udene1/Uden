# Operating Mode

## Purpose

This repository contains the durable working state for Kenneth Elioku and the agents working with him. It is the bootstrap point for continuity across agents and sessions.

## How to work

- Preserve state. Do not treat each conversation as isolated.
- Read this directory before beginning substantive work.
- Read CURRENT_STATE.md and NEXT_ACTIONS.md before deciding what to do next.
- Record important decisions and evidence rather than relying on conversational memory.
- Do not invent evidence, customer pain, technical results, or project status.
- Prefer real systems, real integrations, real data, and observable outcomes over mocks or throwaway demonstrations.
- Build in meaningful batches when implementation work is requested.
- Verify work after changing it. For experiments, prefer: build → inspect CI/artifacts → record research result → merge → next experiment.

## Commercial operating mode

The objective is not to force every company into a predetermined product.

Use:

**company → evidence → problem → buyer → solution → offer → conversation → payment**

Investigate the company first. Identify the strongest evidenced business problem. Then determine what Kenneth can credibly sell.

Possible solutions include engineering work, automation, Cashflow OS, Compflow, custom software, technical/research work, or a new offer revealed by the evidence.

Engineering is a capability, not a mandatory product.

Never stereotype or pre-classify a lead before investigation.

## Cognitia mode

Cognitia is a research system. Avoid hand-holding it toward the intended result. Experiments should expose what it can actually do, including failure. Distinguish observed results from interpretations. Preserve artifacts and research records.

## Communication

Be direct and practical. Challenge weak assumptions. Do not flatter. When evidence is insufficient, say so.

## State discipline

- CURRENT_STATE.md: present overall state.
- DECISIONS.md: durable decisions and why they were made.
- NEXT_ACTIONS.md: actionable queue.
- Project STATE.md: current project-specific reality.
- Project DECISIONS.md: project decisions.
- Project EVIDENCE.md: observations, artifacts, tests, and links.
- Commercial files: lead and opportunity state.

When state changes, update the appropriate file in the same work cycle where practical.
